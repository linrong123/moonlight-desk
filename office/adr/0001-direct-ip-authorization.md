# ADR 0001：首期采用 IP 直连 + 被控端弹窗授权

- 状态：Accepted（2026-11-19）
- 范围：Moonlight Desk、Sunshine Desk

## 背景

目标是对齐主流远控的连接体验，同时满足两个约束：仓库公开，不能依赖私有服务器；必须能持续合并 Moonlight/Sunshine 上游。原有流程需要在被控端网页后台建账户并输入 PIN，跨网只能自行组网或端口映射。

## 决策

1. 首期只支持输入 IP/域名直连，不做设备号和内置中转。
2. 首次授权沿用 GameStream PIN 配对，被控端改为原生弹窗输入主控端显示的 4 位验证码。
3. 已授权设备默认免确认（无人值守），被控端可开启「每次连接需本机确认」，通过新增的已认证 HTTPS 扩展 `office/connect-request` 实现非阻塞确认。
4. 被控端默认强制串流加密。
5. 中转只预留数据模型，以后由用户自建，仓库不内置默认地址。

详细约定见 [直连与授权设计](../CONNECTION.md)。

## 备选方案

- 自建设备号协调 + 中转服务：体验最接近 ToDesk，但公开仓库需要内置或运营服务器，工作量最大，推迟到用户自建中转阶段。
- 内置 WireGuard/Tailscale 组网：改动小，但绑定外部组网方案，交互不像远控，且国内 UDP 质量不稳定。
- 弹窗只点「允许」：最省事，但同网段并发请求可被误放行，且需修改配对协议，放弃。
- 阻塞 `/launch` 等待确认：Sunshine 的 HTTPS 服务是单线程，阻塞会卡住其他客户端请求，放弃，改为独立的请求/轮询接口。

## 后果

- 公网使用仍需用户自行端口映射或组网，文档需说明只开放串流端口。
- 官方 Moonlight 仍可配对与连接；开启每次确认后，官方客户端需在被控端批准后手动重试。
- 强制加密会拒绝不支持加密的旧客户端，并略增 CPU 开销。
